# 小说主流程异常处理复盘（2026-10-13）

## 范围与结论

基线：`7a3e02a`。本轮以小说创作主链、共用任务接口及其页面为范围，核对需求合同、实现和现有测试；视频链只做异常机制的快速盘点，不宣称已完成视频端到端验收。本记录是静态复盘加已有测试证据，**不是**进程故障注入、真实模型加真实 MySQL 的完整验收。

结论：系统已具备来源版本校验、同范围任务冲突、候选与正式资产隔离、取消后的写入拦截和正文长度门禁等保护，但长任务恢复、分段检查点和失败出口尚未连成闭环。继续以人工点击逐步找问题，会反复把模型费用和测试时间花在前面已经成功的部分。应先完成下列稳定性门禁，再扩大内容质量和完本验收。

## 现有有效保护

- 新任务 claim 前验证必需来源引用，并在调用模型前及结果写入前再次核对权威来源；同范围任务冲突与幂等键能阻挡常见重复提交。见 `apps/api/src/modules/novels/services/taskClaim.ts`。
- 正文超长原稿保留为候选，超长修订最多一次且不自动采用；修订候选尚无复核链路，故服务端阻止它成为正式正文。见 `apps/api/src/modules/novels/services/novelService.ts`。
- Prisma 仓储已有 worker 租约、心跳、过期恢复和结果 fencing 方法，也有批量正文逐章事务写入能力。这些是可复用的基础，但不能把“仓储方法存在”记作生产调用链已经可恢复。
- 隔离 mock 的 125 秒跨刷新等待测试通过；后端单测、质量资产测试和类型检查通过。真实模型内容验收仍未通过，见 `novel-urban-rebirth-content-canary-2026-10-13.md`。

## 执行顺序和放行门槛

1. **先封住不可恢复任务（E1）**：建立真实排队/worker/恢复链，先用故障注入证明任务不会永久卡住、不会自动重复付费。没有这条门禁，不再用长时间人工等待推进后半程。
2. **再保住已付费的分段成果（E2/E3）**：正文逐章和目录逐段落检查点，能定位失败点并从缺口续跑；每个结果保留来源引用与版本历史。
3. **补齐失败出口与真实库边界（E4/E6/E7）**：同一种错误在任务中心和业务页给出一致解释；未实现能力在点击前可见；真实库正式写链逐步验收。
4. **最后放行内容质量（E5）**：字数、结构、对话、事实承接、章节记忆和人工阅读分别有证据；失败样本入固定回归集，不因 mock 或长度合格直接宣布通过。

每项必须同时交付：可复现故障用例、任务/资产/费用断言、用户可理解的恢复动作、失败日志脱敏核对、真实环境或隔离环境边界说明。至少覆盖超时、429/额度不足、非法/截断 JSON、模型输出字段不符合系统 schema、途中取消、来源版本变化、数据库提交失败、进程重启、前端断网刷新，以及批量第 k 段失败。人工浏览器验收用于确认交互和内容，不能代替这些确定性的异常测试。
