## 隔离 MySQL

- 本机 Docker MySQL 8.4.11，数据库 `ai_shortvideo_novel_test`，端口仅绑定 `127.0.0.1`；未连接生产库。容器为一次性测试容器，未保存数据库密码到仓库。
- 从空库执行 `prisma migrate deploy`，按顺序成功应用 7 条迁移，包括独立分支 `codex/novel-db-baseline-20261012` 的初始迁移草案 `c2d8efa`。
- 迁移后的数据库与当前 Prisma schema 对比：小说相关只有 `create_novel_preferences` 的索引名称差异；另有 5 张视频表及视频字段缺口。不能声称整个当前 schema 已对齐。
- Prisma 模式下创建小说草稿返回 201，详情读取返回 200；关闭应用后在新进程中再次读取详情和列表，均返回 200。该样本仅覆盖草稿持久化，未覆盖正文、全书审稿或完本写入。
- 使用 mock provider 和合成都市逆袭草稿，在 MySQL 中对同一小说的两个方向候选并发提交采用，连续 3 轮均为一次 200、一次 409 `VERSION_CONFLICT`；每轮只有一个 current，另外三个候选为 historical。另一次独立运行的新进程读取为 200、`creationStage=setting`，current 指针与唯一当前候选一致。没有消耗真实模型额度，也没有测试其他资产类型的并发采用。

## 真实模型

- 使用现有 `chapterLengthLiveSmoke.ts`，每次最多 1 次模型调用、3600 个输出 token；没有写数据库，也没有记录完整提示词或正文。
- 初次调用 `deepseek-v4-pro` 返回空内容，约 43 秒后安全失败。客户端此前未保留服务端结束原因。
- 在正文生成和重写请求中显式关闭思考模式后，复测 1 次成功：目标 800 字，实际 851 字，允许区间 720-920 字；使用 518 个提示词 token、2624 个输出 token，耗时约 51 秒。正文 SHA-256 为 `44881dde82bbd7e531012d11dbb306b08488f1ddae36f63ff2c5b7b242256a61`。
- 这次 canary 是独立短篇场景，不是用户选定的都市逆袭/重生内容质量样本。输出长度合格不能推断故事精彩，也不能证明目录、试写、批量正文和审稿链路稳定。脚本中的美元预算字段是计划上限，尚无实时费用扣费验证。

## 后续验证：输出边界和长等待交互

- 按上述需求及 `docs/modules/model-integration-m1-deepseek-provider.md` 的结构化输出约束复核后，给方向评分、结构候选必需字段、章节目录的数量/顺序/目标字数增加硬校验。空结构、越界评分、缺章、重复章和超出小说字数区间的目录不会被补成可采用候选。允许缺省的章目标字数仅在本小说已配置范围内取中间值。
- 隔离 MySQL 中沿用合成都市逆袭/重生样本，注入返回 `{}` 的假模型生成设定：HTTP 500，任务 `FAILED` 且 `failureCategory=output_parse_failed`，设定候选计数和正式设定指针不变。此测试不调用真实模型，不代表模型质量通过。
- 浏览器用受控延迟模型串了“生成设定 -> 刷新 -> 新页面 -> 查看同一任务 -> 模型返回 -> 候选出现”：等待超过一次 5 秒轮询，后端只有一个任务和一次设定模型调用。再注入连续两次无效大纲结构，确认任务失败且无大纲候选；刷新后重新生成有效结构，候选出现，正式资产仍需手动采用。可复现命令为 `npm run e2e:novel-wait`。
- 模型单次默认超时由 60 秒调整为 360 秒，默认传输自动重试由 1 次改为 0 次；覆盖通常 2-5 分钟响应并避免超时自动重复付费。**未做真实 2-5 分钟线上模型等待验收**，也未证明浏览器/网关在长 HTTP 请求上不会超时。
- 当前普通生成仍在 HTTP 请求内等待 provider，未做到立即返回真实任务 ID、进程重启后恢复、超时后任务租约回收。浏览器轮询只能覆盖进程持续运行的场景；这项不能标为完整通过。正文 Prisma 路径也仍未实现，不能据本次设定/大纲成功推断小说已能完本。
- 回归：API 单测 183/183，质量基准 4/4；前端单测 80/80、DOM 32/32；全仓类型检查通过。以上是研发自测，尚未替代独立测试会话和都市逆袭/重生内容人工盲评。
