## 隔离 MySQL

- 本机 Docker MySQL 8.4.11，数据库 `ai_shortvideo_novel_test`，端口仅绑定 `127.0.0.1`；未连接生产库。容器为一次性测试容器，未保存数据库密码到仓库。
- 从空库执行 `prisma migrate deploy`，按顺序成功应用 7 条迁移，包括独立分支 `codex/novel-db-baseline-20261012` 的初始迁移草案 `c2d8efa`。
- 迁移后的数据库与当前 Prisma schema 对比：小说相关只有 `create_novel_preferences` 的索引名称差异；另有 5 张视频表及视频字段缺口。不能声称整个当前 schema 已对齐。
- Prisma 模式下创建小说草稿返回 201，详情读取返回 200；关闭应用后在新进程中再次读取详情和列表，均返回 200。该样本仅覆盖草稿持久化，未覆盖正文、全书审稿或完本写入。
- 使用 mock provider 和合成都市逆袭草稿，在 MySQL 中对同一小说的两个方向候选并发提交采用，连续 3 轮均为一次 200、一次 409 `VERSION_CONFLICT`；每轮只有一个 current，另外三个候选为 historical。另一次独立运行的新进程读取为 200、`creationStage=setting`，current 指针与唯一当前候选一致。没有消耗真实模型额度，也没有测试其他资产类型的并发采用。

## 真实模型

- 使用现有 `chapterLengthLiveSmoke.ts`，每次最多 1 次模型调用、3600 个输出 token；没有写数据库，也没有记录完整提示词或正文。
- 初次调用 `deepseek-v4-pro` 返回空内容，约 43 秒后安全失败。客户端此前未保留服务端结束原因。
- 在正文生成和重写请求中显式关闭思考模式后，复测 1 次成功：目标 800 字，实际 851 字，允许区间 720-920 字；使用 518 个提示词 token、2624 个输出 token，耗时约 51 秒。正文 SHA-256 为 `44881dde82bbd7e531012d11dbb306b08488f1ddae36f63ff2c5b7b242256a61`。
- 这次 canary 是独立短篇场景，不是用户选定的都市逆袭/重生内容质量样本。输出长度合格不能推断故事精彩，也不能证明目录、试写、批量正文和审稿链路稳定。脚本中的美元预算字段是计划上限，尚无实时费用扣费验证。

## 后续验证：输出边界和长等待交互

- 按上述需求及 `docs/modules/model-integration-m1-deepseek-provider.md` 的结构化输出约束复核后，给方向评分、结构候选必需字段、章节目录的数量/顺序/目标字数增加硬校验。空结构、越界评分、缺章、重复章和超出小说字数区间的目录不会被补成可采用候选。允许缺省的章目标字数仅在本小说已配置范围内取中间值。
- 隔离 MySQL 中沿用合成都市逆袭/重生样本，注入返回 `{}` 的假模型生成设定：HTTP 500，任务 `FAILED` 且 `failureCategory=output_parse_failed`，设定候选计数和正式设定指针不变。此测试不调用真实模型，不代表模型质量通过。
- 浏览器用受控延迟模型串了“生成设定 -> 刷新 -> 新页面 -> 查看同一任务 -> 模型返回 -> 候选出现”：等待超过一次 5 秒轮询，后端只有一个任务和一次设定模型调用。再注入连续两次无效大纲结构，确认任务失败且无大纲候选；刷新后重新生成有效结构，候选出现，正式资产仍需手动采用。可复现命令为 `npm run e2e:novel-wait`。
- 模型单次默认超时由 60 秒调整为 360 秒，默认传输自动重试由 1 次改为 0 次；覆盖通常 2-5 分钟响应并避免超时自动重复付费。**未做真实 2-5 分钟线上模型等待验收**，也未证明浏览器/网关在长 HTTP 请求上不会超时。
- 当前普通生成仍在 HTTP 请求内等待 provider，未做到立即返回真实任务 ID、进程重启后恢复、超时后任务租约回收。浏览器轮询只能覆盖进程持续运行的场景；这项不能标为完整通过。正文 Prisma 路径也仍未实现，不能据本次设定/大纲成功推断小说已能完本。
- 回归：API 单测 183/183，质量基准 4/4；前端单测 80/80、DOM 32/32；全仓类型检查通过。以上是研发自测，尚未替代独立测试会话和都市逆袭/重生内容人工盲评。

## 后续验证：试写正式化、页面串联与交互

- 浏览器在内存仓储、mock provider 下，人工逐页走通 8 章合成都市重生小说：创建草稿、方向/设定/全书及阶段大纲/章节目录候选生成与采用、第 1 章试写和第 2-3 章续写、试写确认、第 4-8 章批量正文、全书审稿、完本确认。此结果只证明该模拟路径的页面入口与状态转换可串联，不证明 Prisma 正文落库、真实模型内容质量或用户实际完本。
- 隔离 MySQL/Prisma、mock provider 的同类 8 章样本走到试写确认时，原实现只记录试写策略快照，第 1-3 章仍是 `trial_written`，批量正文随后返回 `409 GATE_BLOCKED`。已在 Prisma 试写确认事务内加入逐章版本指针校验和条件更新，将已确认的三章提升为 `completed`；校验不通过时事务回滚，不产生部分正式化。
- 用新合成样本复测后，第 1-3 章 `main_status=completed` 且正文版本指针可回读。下一步批量正文明确返回 `500 CONFIG_MISSING`：Prisma 后半段写链尚未实现，数据库中没有新建 `body_batch_generate` 任务。可复现的安全脚本为 `npm run e2e:novel-prisma-trial-gate`；它仅允许本地隔离测试库与 mock provider，保留带 `SMOKE-` 前缀的测试数据供回读，不调用真实模型。
- 页面交互巡检发现并修复：设定采用后大纲页仍错误提示“先采用设定”；首次试写尚无候选时却显示“重新生成 3 个”；第 1 章结果、全书/阶段大纲结果的任务入口文案不区分对象；任务成功后仍保留“正在调用模型”的旧步骤；长等待提示从 1-3 分钟调整为 2-5 分钟。设定仍在当前 HTTP 请求内等待时，原“取消等待/重新生成”并不能真正取消服务端任务，已移除这组误导动作，保留“查看任务进度”，并明确失败或超时后才可重试。
- 交互遗留：普通生成仍依赖持续中的 HTTP 请求；当前页面不能真正取消/重试尚未返回的模型调用，也没有进程重启恢复保障。任务取消、重试和迟到结果的统一语义仍需按 RP-02 服务端任务平台完成后独立验收。窄屏“最近任务”状态文案可能换行，部分页面有重复生成入口，需后续 UI 收敛；本轮不将这些视为已通过。
- 本轮回归包括 API 单测、前端单测及 DOM 测试、全仓类型检查、长等待浏览器脚本和上述 Prisma 门禁脚本；独立测试验收、真实 2-5 分钟模型调用、常规 2,000-3,500 字章节与人工内容盲评仍未完成。

## 继续验证：常规章节质量与两分钟等待

- 将浏览器内存仓储和受控假模型的设定生成保持 125 秒：发起页始终显示生成中，第二个页面刷新后能回到同一任务，服务端仅调用模型一次；释放后发起页与新页面均看到候选。`NOVEL_WAIT_HOLD_MS=125000 npm run e2e:novel-wait` 通过。这证明页面在持续运行的本地进程内可以承接超过两分钟的等待，**不证明**真实 provider、网关、进程重启恢复或五分钟请求通过。
- 对固定都市逆袭/重生样本作三次单次、零自动重试的真实模型调用，均未写入数据库。第一次 2,300 字目标返回 2,420 字，耗时约 53 秒，长度合格但内容换成了另一位女主角的直播恋爱重生故事，未遵循已采用的林越、仓库旧账与父亲签字主线，因此**业务质量不通过**。定位到正文 provider 只发送了策略快照 ID，未发送已采用策略的标题和摘要；现已补齐并加请求单测。
- 补齐策略上下文后的第二次调用返回非法 JSON；增加安全诊断后第三次调用定位为输出达到 5,520 token 上限（`finishReason=length`、`completionTokens=5520`），JSON 被截断。错误现在区分截断与普通非法 JSON，只返回结束原因、token 数和响应字符数等元数据，不记录正文或完整模型响应。
- 单章正文/重写的输出预算按目标字数提高至最多 9,000 token；试写候选的原预算保持不变，避免扩大其他任务的费用与等待。固定样本 canary 增加主角和关键情节锚点校验。这些是**基于失败证据的代码修正，尚未再做付费模型复测**，不能宣称常规章节真实生成通过；固定词锚点也不等同于通用的情节一致性评审。
- 本轮 API 单测 186/186、全仓类型检查通过。待验门禁：预算调整后的常规章节真实模型复测、人工核查内容是否承接已采用策略、长请求跨进程/网关承接，以及 Prisma 正文分批写入与完本链路。当前不能把小说标为已生成完毕或质量验收通过。

## 继续验证：单章复测与失败后重试

- 在提高单章输出预算后，对同一都市重生固定样本再作 **1 次真实 `deepseek-v4-pro` 调用，零重试、零数据库写入**。约 59 秒返回完整结构化结果；目标 2,300 字，按项目统一的非空白字符口径计 2,880 字，超出允许的 2,070-2,645 字；提示词 670 token、输出 3,655 token，未再次触及 token 截断。正文 SHA-256 为 `7d655d09291a0e3267579f1363a96aeecb0cac6daf5f2c171c92a852d9bceb42`。主角、仓库、账本和父亲四个固定锚点均出现，但**长度门禁不通过**。
- 人工初读发现三处需修正的叙事问题：同一笔货款先被说成到账、后又说未进入林家账户，缺少区分；疑似伪造的账页既被描述为不同纸质，又与原账本撕口严丝合缝；刚结束高考的主角自称学过会计。这是单样本人工检查，不是独立盲评；单靠锚点出现不能证明人设和逻辑连贯。
- 针对短/超长模型输出重跑服务接口测试：第 1 章与后续试写，以及批量正文、单章正文、章节重写均返回 `409 GATE_BLOCKED`，任务记为 `content_length_out_of_range`，正式章节资产不写入。当前安全门禁有效，但超长正文也不会留下可编辑候选，用户只能再次付费生成，属于恢复体验缺口。
- 页面复核发现批量正文遇到明确的字数越界失败后仍保留旧幂等键，重复点击会复用失败任务。已改为仅在服务端明确返回 `NOVEL_CONTENT_LENGTH_OUT_OF_RANGE` 时换新键；网络中断等结果不明的情况仍复用原键，避免重复付费。DOM 测试验证了“网络不明 -> 原键；确定长度失败 -> 新键”，完整 DOM 34/34、全仓类型检查通过。
- 仍未通过：常规章节长度与内容质量的联合验收。当前正文 provider 的章节输入只含章号、标题、目标字数和状态备注，没有目录中的本章目标、冲突、钩子等情节约束；已采用的策略摘要不能替代这些逐章约束。Prisma 正文写链也仍未实现，因此不能继续宣称真实数据库小说完本。

## 继续验证：现行 15% 容差与浏览器回归

- 用户确认目标字数上下各允许 15% 后，对固定都市重生样本进行 **1 次真实 `deepseek-v4-pro` 调用，零自动重试、零数据库写入**。目标 2,300 字，现行合格区间 1,955-2,645 字，实际 3,913 字，仍为 `too_long`；耗时约 72 秒，提示词 670 token、输出 4,772 token。正文 SHA-256 为 `18c8158dd2cb1edb8fb96f441817084a456c7d41d1f30d9e32eb1d418e8aa163`。四个固定情节词均出现，但不构成内容质量通过。
- 人工初读发现明确的时间线矛盾：故事开头日期为 2009 年 7 月 12 日，主角当天找到的既有账页却记录了 7 月 15 日的借支。这是单样本检查，尚非独立盲评；与超长结果一起将常规章节联合验收维持为 **未通过**。现有字数提示已发送给模型，但不能保证其遵守，因此不宜仅放宽门禁或连续付费重试。
- `npm run e2e:novel-wait` 通过：受控假模型下，同一设定任务在等待和刷新后保留，非法大纲输出不生成候选，重新生成可以恢复。无真实模型调用、无数据库写入。
- `npm run e2e:rp04c` 初跑被测试中旧的“1-3 分钟”断言阻断；页面实际按当前 2-5 分钟提示显示。修正断言和产品文档后重跑通过：12 章模拟样本覆盖全书审稿、持续等待、刷新/第二标签页承接、失败后刷新恢复，证据在 `output/playwright/rp-04c/rp04c-2026-10-12T13-55-38-623Z/safe-evidence.json`。该次证据标记工作树有测试修正，不能伪称为干净提交上的独立验收；模拟路径亦不能证明真实数据库正文写入或真实内容质量。
- 后续阻塞顺序：先让正文生成受权威章节目标、冲突和钩子约束，并解决超长结果的显式恢复体验；随后在同一固定样本上复测长度与情节，再推进隔离 MySQL 的 Prisma 分批正文、失败恢复、全书审稿和完本回读。当前不声明小说生成完毕。
