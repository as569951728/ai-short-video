# 小说优先交付与内容质量验收

更新日期：2026-10-12。本文记录当前优先级和交付门槛，不替代问题总账，也不把已有 mock 流程视为真实完本。

## 范围

- 当前只推进小说从创建、方向、设定、大纲、目录、试写、批量正文、全书审稿到用户确认完成的闭环。
- 内容质量是交付条件，不以接口成功、模型自评分、字符数合格或页面可点击单独证明“精彩”。首轮固定样本沿用用户确认的“都市逆袭/重生”题材。
- 视频生产、TTS、字幕、渲染、导出和发布暂缓。未来可评估第三方工具，但不让视频链路阻塞小说完成确认。
- 真实模型调用与真实数据库写入只在隔离测试环境、安全预算和回滚方案明确后执行；普通测试使用 mock。

## 交付顺序

| 阶段 | 可验收结果 | 当前事实 |
| --- | --- | --- |
| 1. 数据库底座 | 从空的隔离 MySQL 测试库应用完整迁移，小说基础表、索引和唯一性可验证 | 现有迁移目录只有增量迁移，没有小说基础表的初始迁移；本机无可连接的本地数据库 |
| 2. 正文生产 | Prisma 模式第 4-5 章可分批写入、回读和重启恢复；幂等、冲突、失败保留及跨章记忆有证据 | `createBodyBatchTask`、`generateBodyBatch` 等 Prisma 路径仍未实现；本轮先修批次内记忆传递 |
| 3. 审稿与完结 | 全书报告、问题门禁和完成决定在同一权威数据库可追溯；旧版本与阻塞问题不能放行 | Prisma 的全书审稿和完结写入仍未实现 |
| 4. 真实模型稳定性 | 固定样本按费用上限跑通章节目录、试写和正文；超时/格式错误可恢复，失败不留可采用产物 | 现有真实模型证据不足；不得用 fake client 替代 |
| 5. 内容质量 | 版本化正反样本覆盖人物事实、爽点兑现、开头/章末钩子、重复和 AI 味；真人盲评复核，再对固定小说做完整阅读验收 | 首个都市逆袭/重生人物连续性配对样本已加入测试，金标仍待人工复核；其余维度未覆盖 |

每阶段只在对应的代码、测试和独立验收证据到位后推进。真实完本至少要证明：从空测试库启动、完整生成并确认、服务重启后资产保持、失败重试不重复写、版本和审计可追溯。最终内容验收要由读者指出具体段落和跨章证据，并回答“是否愿意继续读”；模型自评分只能作为待校准信号。

## 当前首个改动的边界

批量正文的下一章应读取上一章刚生成的记忆，而非整个批次重复读取启动时的旧记忆。不可矛盾事实须在批内传递和最终保存时保留；人物状态、关系状态和未解冲突仍需更完整的长期记忆算法。该改动只改善批次内上下文传递；不等于持久 checkpoint、失败段续跑、真实 MySQL 完本或内容质量通过。
