# 超长正文恢复与候选采用验收契约

状态：待实现、待独立验收。适用于单章生成和批量正文中某一章首次超过当前权威目标字数上限的情况。现行长度区间见 [章节字数规则](novel-chapter-length-policy.md)。本文不放宽长度门禁，也不授权自动改写正式正文。

## 用户流程

1. 首次正文返回超长时，保留原稿为可查看的候选版本，标明实际字数、目标区间和超出量；不更新章节当前正文、特性卡、审稿或长篇记忆指针。任务明确显示“超长待处理”，批量生成停在该章，不请求后续章节。
2. 用户可查看原稿、手工编辑候选，或明确发起一次 AI 精简。AI 只选择服务端枚举的完整冗余句编号，服务端计算最小合规删减组合；无合规组合时保留原稿并说明原因，不追加自动模型重试。新稿另存为候选，不能覆盖原稿。
3. 页面并排给出原稿与修订稿字数、删句差异及质量提示。修订稿字数合格只表示通过长度门禁，不表示情节、人物和因果已通过。用户可放弃候选或选择一稿进入复核；超长原稿不能直接采用。
4. 采用前，必须针对**所选版本**生成或确认对应的章节特性卡、单章审稿和长篇记忆。原稿的模型自评分、摘要及记忆不能复制成修订稿的有效证据。影响评估和必要的人工确认完成后，才可原子切换当前正文及配套证据指针，并继续后续章节。

## 服务端边界

- 候选包含 tenant、novel、chapter、sourceTask、sourceVersionRefs、版本号、来源类型、正文、计数字段、创建时间和安全的修订关系；原稿与修订稿各有独立 ID。完整提示词和模型原始响应不进入候选元数据、任务摘要或普通日志。
- 同一章同一来源任务的结果必须幂等；重复请求或页面刷新只回读已存在任务与候选，不重新调用模型。取消或任务失租后的迟到输出不得成为当前版本。
- 批量任务在第 N 章待确认时，已完成的前 N-1 章及其证据保留，N+1 章及以后保持未生成；下一批的上一章正文与长篇记忆只能读取当前正式版本，绝不读取候选。
- 采用操作校验权威字数目标、候选状态、当前版本指针、策略和目录来源版本、任务状态、租户范围及冲突任务。事务内保存决策记录、操作日志和前后版本；旧当前版本转历史。并发采用只能有一个成功。
- 若候选仍缺少与其 contentVersionId 严格绑定的特性卡、审稿或记忆，采用应被阻断并给出复核入口；不能把旧版本的评分或记忆当成新稿结论。
- Prisma 普通正文写链已在本地隔离 MySQL 上用 mock provider 跑通，但超长候选恢复入口仍未开放；当前实验删句模式保持默认关闭，服务层拒绝将修订稿直接写成正式正文。

## 最低验收用例

| 用例 | 必须观察到的结果 |
| --- | --- |
| 首稿超长、刷新和第二标签页 | 同一任务、同一原稿候选；正式指针不变，下一章未调用模型 |
| 精简成功及失败 | 成功产生独立修订候选且长度合格；失败保留原稿，无第三次自动付费调用 |
| 精简稿事实复核不通过 | 可放弃或手工编辑；不会因字数合格自动采用或继续批次 |
| 采用与证据绑定 | 当前正文、特性卡、审稿、记忆来自同一候选；旧版本和决策日志可回读 |
| 并发、重复和迟到回调 | 不产生双 current、重复候选、重复费用或正式资产静默覆盖 |
| 隔离 MySQL 重启回读 | 候选、任务、已完成章、暂停位置及采用结果均可在新进程中读取 |

模拟 provider 和内存仓储测试只能证明交互/状态逻辑；上述真实数据库用例需在安全隔离 MySQL 上执行。真实模型的长度与情节质量仍要用固定都市逆袭/重生样本人工复核，不能由 mock 或模型自评分替代。
